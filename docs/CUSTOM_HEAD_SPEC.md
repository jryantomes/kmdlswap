# Custom heads: structure and acceptance criteria

What a custom head has to look like on disk, and what it has to satisfy before
this tool will build it into a model.

Every threshold below is **measured from the 33 head meshes the game already
ships**, not chosen by taste. A mesh the engine is known to render is the only
honest definition of acceptable, and a rule vanilla itself would fail is a wrong
rule — there is a test asserting exactly that.

## Structure

A head is a folder. Deliberately plain: no archive, no database. Something a
person can inspect, edit and hand to someone else without this tool.

```
my_head/
  head.obj      required   the geometry
  head.tga      optional   a texture; its filename becomes the resref
  head.json     optional   metadata and fitting hints
```

`head.json` carries only what cannot be read off the mesh:

```json
{
  "name":   "Tripo Alien",
  "author": "someone",
  "notes":  "generated by Tripo, retopologised",
  "target": "head",
  "facing": "-y",
  "scale":  1.15,
  "anchor": "chin"
}
```

Everything in it is a **hint**. Nothing is trusted over what the geometry
actually says, and a pack with no manifest at all is valid.

```bash
kmdlfun head my_head --template            # write a head.json to fill in
kmdlfun head my_head                       # check the mesh on its own
kmdlfun head my_head --install "<K1>" --host p_hk47 --node head
kmdlfun head my_head --install "<K1>" --host p_hk47 --node head --out build/
```

## Criteria

Graded, not pass/fail: *worse than any vanilla head* and *impossible* are
different things, and the user should be told which.

### Mesh

| Check | Pass | Warn | Reject | Vanilla |
|---|---|---|---|---|
| Connected pieces | ≤ 2 | 3–4 | > 4 | median 1, worst 2 |
| Open (boundary) edges | ≤ 6.2% | ≤ 15% | > 15% | median 1.8%, worst 6.2% |
| Triangles | 440–796 | < 440, or ≤ 1500 | > 1500 | median 690 |
| Winding vs normals | ≤ 5% disagree | > 5% | — | — |
| Texture coordinates | present | absent | — | — |
| Degenerate faces | none | any | — | — |

Those first two rules exist because of a real failure. The first Tripo head this
project produced had **6 components and 22% open edges**, and in-game it read as
a hollow faceted shell with a fragment floating beside it. These checks would
have caught it before anything was built.

### Target

| Check | Meaning |
|---|---|
| Authorable columns | The node must need only `vertex`, `normal` and one UV set. A node carrying `uv2`, vertex colour or tangent frames is **rejected** — an OBJ cannot express them and inventing them is not acceptable. |
| Skinned head | A **warning**, not a refusal. A skinned mesh in a head model cannot change its vertex count or facial animation breaks, so the custom mesh is used as a *shape to reshape onto* — the host keeps its own vertices, UVs and weights. |
| Unskinned target | The mesh's own topology and UVs are used as they are. This is the good case: HK-47 and T3-M4. |
| Whole-model budget | Warns above 4,000 triangles, the brief's practical ceiling. |

### Texture

| Check | Rule |
|---|---|
| Name | ≤ 16 characters — a KOTOR resref. Longer and the game never finds it. **Reject.** |
| Dimensions | Powers of two. **Reject** otherwise. |
| Size | ≤ 512. Heads ship at 256, HK-47's body is 512. **Warn** above. |
| Format | `.tga` (uncompressed) or `.tpc`. **Reject** otherwise. |

## The two paths, and why they differ

This is the structural thing to understand before authoring anything.

**Unskinned head node** — HK-47, T3-M4. The head is a rigid child node. Your
mesh is used directly: its topology, its UVs, its texture. Full freedom over
vertex count and layout.

**Skinned head model** — every human companion. The head is skinned to facial
bones, and *changing its vertex count breaks facial animation* (measured
in-game; see `reports/HEAD_ANIMATION_FINDINGS.md`). Your mesh cannot be used
directly. Instead the host's own vertices are moved onto your mesh's surface,
which means:

- vertex count, faces, UVs and weights stay the host's
- your mesh contributes **shape only**
- the result has the host's resolution — a more detailed mesh cannot express it
- the host's texture stays unless UVs are resampled too (`--with-texture` on
  `transplant`)

So a custom head for a human companion is a *sculpting target*, and one for a
droid is a *replacement*. Author accordingly.

## What is still not covered

- **Nothing validates that the head looks right.** These are structural checks.
  Orientation, proportion and placement are judged by eye, and the `facing`,
  `scale` and `anchor` hints exist because the tool cannot infer them reliably.
- **Adjacency is rebuilt at 96.3% fidelity**, not exactly. No visible
  consequence has been observed, but it is not proven harmless.
- **No check for self-intersection or inverted volume.** A mesh can pass every
  rule here and still be inside-out in a way only rendering reveals.
- **A successful build is not proof.** In-game verification remains the only
  acceptance test that counts.
